# 프로젝트별 논문 규칙

논문 규칙 프로필은 **선택 기능**이다. 브리지를 단순 Overleaf 제어기로 쓰려면
규칙 프로필 없이 연결하면 된다. 학회·저널 형식을 지키며 집필하려는 프로젝트만
프로필을 추가한다. 설치를 다시 하거나 TEST/production 스위치를 설정할 필요는 없다.

## 두 가지 보호층

| 구분 | 항상 사용 | 역할 |
|---|---:|---|
| 연결 안전장치 | 예 | 정확한 project ID, 현재 원문, 한 파일 diff, 동시수정, Track Changes, 저장 결과와 template 기준선을 확인한다. |
| 논문 규칙 프로필 | 아니요 | venue/year/track, 페이지, 익명성, 필수 문구, 언어·용어, 윤리·funding, PDF 제출 규칙을 프로젝트별로 기억하게 한다. |

규칙 프로필이 없더라도 연결과 일반 편집은 가능하다. 반대로 규칙 프로필을 넣었다고
학회 준수가 자동 보증되는 것은 아니다. 브리지가 직접 검사할 수 없는 규칙은 Codex의
검토 또는 저자의 최종 확인 항목으로 남는다.

## 가장 간단한 사용법

### 연결만 사용

```text
이 Overleaf 프로젝트는 논문 규격 룰 없이 연결만 해줘.
```

### 처음부터 논문 규칙과 함께 연결

```text
이 프로젝트는 [학회/저널] [연도] [track] 논문이야.
공식 저자 규정을 확인해서 핵심 규칙을 프로젝트별로 저장하고 연결해줘.
```

venue, 연도 또는 track을 알 수 없을 때만 Codex가 짧게 묻는다. 사용자는 JSON이나
project ID를 직접 입력할 필요가 없다.

### 이미 연결한 프로젝트에 나중에 추가

```text
이 프로젝트에 [학회/저널] [연도] [track] 규칙을 추가해줘.
공식 출처와 확인 날짜도 같이 저장해.
```

### 규칙 교체 또는 제거

```text
이 프로젝트 규칙을 [새 규칙]으로 교체해줘.
```

```text
이 프로젝트의 논문 규칙 프로필을 지우고 연결만 사용하는 모드로 바꿔줘.
```

현재 저장 내용을 확인하려면 다음처럼 말한다.

```text
이 프로젝트에 저장된 논문 규칙과 마지막 확인 날짜를 보여줘.
```

추가·교체·삭제는 Overleaf 문서를 바꾸지 않는다. 다만 규칙 hash가 바뀌므로 그전에
만들어 둔 미승인 diff는 폐기되고 현재 원문으로 다시 preview해야 한다.

## 프로필에 저장되는 내용

- 규칙 이름: venue, year, track 또는 팀 내부 규칙명
- 규칙 revision과 검토 시각
- 공식 출처 URL
- 각 규칙의 정확한 요구사항과 필수/권고 여부
- 검사 방법
- 필요한 비고와 예외

검사 방법은 다음처럼 구분한다.

| 검사 종류 | 예 | 의미 |
|---|---|---|
| `source_diff` | document class, 익명 저자 표기, 금지된 layout 명령 | 현재 LaTeX와 제안 diff에서 확인 |
| `compile_pdf` | 페이지 수, overflow, 참고문헌 위치 | 컴파일 결과와 PDF에서 확인 |
| `human_final` | 저자 순서, funding, ethics, 최종 익명성 | 제출 전 사람이 확인 |
| `live_official` | 마감, 제출 사이트, 변경 가능한 정책 | 공식 사이트를 다시 열어 확인 |
| `advisory` | 용어, 문체, 팀 내부 선호 | 작성 지침으로 적용 |

한 규칙에 여러 검사 방법을 지정할 수 있다. 예를 들어 페이지 제한은
`compile_pdf`와 `human_final`을 함께 사용한다.

## 저장 위치와 여러 논문

브리지는 프로필을 Mac의 비공개 bridge state에 project ID별로 저장하고 hash와
과거 revision을 보존한다. `overleaf_status`로 해당 프로젝트를 읽을 때 현재 프로필도
함께 반환되므로 Codex 앱과 SSH 서버의 Codex CLI가 같은 Mac bridge를 쓰면 동일한
규칙을 확인할 수 있다.

논문 A의 규칙, 예외 또는 승인은 논문 B로 넘어가지 않는다. 새 논문은 그 탭에서
한 번 연결하고, 필요할 때만 그 논문의 규칙을 추가한다.

여러 사람·여러 Mac에서 같은 규칙을 공유하려면 채운
`approved-bridge/PROJECT_POLICY_TEMPLATE_KO.md`를 논문의 비공개 코드 저장소에
보관하는 방법을 권장한다. 브리지에는 그 문서의 SHA-256도 선택적으로 연결할 수
있다. 비공개 Overleaf 공유 링크, cookie와 bridge token은 규칙 파일에 넣지 않는다.

## 변경되는 공식 규칙

연도, track, deadline과 제출 정책은 바뀔 수 있다. 프로필의 `reviewedAt`은 “그
시점에 검토한 요약”을 뜻하며 영구적인 최신성 보증이 아니다. `live_official`로
표시한 항목은 최종 제출 전에 공식 출처를 다시 확인하고, 내용이 달라졌으면 새
revision으로 교체한다. 과거 revision은 rollback·감사 기록으로 남는다.
